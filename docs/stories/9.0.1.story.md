## Story

**As a** dev,
**I want** os dois apps com bundle identifier, versão válida e usage
descriptions mínimas de iOS,
**so that** o EAS Build gere um IPA aceitável pelo App Store Connect.

## Acceptance Criteria

1. `apps/cliente/app.json` recebe `ios.bundleIdentifier = "com.keepithub.cliente"`
   e `apps/lojista/app.json` recebe `ios.bundleIdentifier = "com.keepithub.lojista"`
   (valores já confirmados com Caio, ver Dependencies — não é decisão desta
   story). [Fonte: `docs/prd/epics/9-publicacao-compliance.md`, Story 9.0.1 AC1]
2. `version` de `"0.0.0"` → `"1.0.0"` nos dois apps, e `ios.buildNumber = "1"`
   declarado (App Store Connect rejeita `0.0.0`). [Fonte: idem, AC2]
3. `infoPlist` declara **apenas** o que o build realmente usa em mock.
   Confirmado por leitura (Dev Notes): nenhum dos dois apps instala
   `expo-camera`, `expo-location` ou `expo-notifications`, e `ModalPermissaoPush`
   (Cliente e Lojista) é puramente visual — não chama nenhuma API nativa de
   permissão. Portanto, **nenhuma chave de `infoPlist` é adicionada** nesta
   story. Se, durante a implementação, algum desses pacotes passar a ser
   consumido, declarar apenas a usage description correspondente — não
   antecipar. [Fonte: idem, AC3]
4. `npx expo-doctor` (ou `eas build --platform ios --profile pilot --local`,
   se a Story 9.0.2 já estiver concluída) não acusa campo iOS obrigatório
   ausente para os dois apps.
5. Nenhuma fixture mock alterada; os dois apps continuam abrindo em
   `DATA_SOURCE=mock` (comportamento inalterado — esta story não toca
   `packages/core-data`).
