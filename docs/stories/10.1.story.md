## Dev Notes

- **App Router / RSC:** `app/layout.tsx` e `(dashboard)/layout.tsx` são Server
  Components hoje. O provider e o guard precisam ser Client Components
  (`'use client'`). Não transformar o root layout inteiro em client — apenas
  inserir o provider (client) como wrapper dentro do `<body>`.
- **Por que `sessionStorage` e não cookie:** mock puro client-side, sem
  middleware/SSR de auth; `sessionStorage` sobrevive a refresh e some ao fechar
  a aba — adequado para demo. Evita complexidade de cookies/edge middleware
  (princípio "backend simples" do CLAUDE.md).
- **Padrão de referência:** `packages/core-data/src/mock/auth.mock.ts` (Cliente)
  — `signIn` por e-mail ignorando senha, `signOut`, pub/sub. Aqui é a mesma
  ideia, porém **local ao Admin** e sem tocar core-data.
- **Guard atual:** `src/config/authGuard.ts` (`AUTH_GUARD_ENABLED=false`,
  `isAuthenticated()===true`) e `app/page.tsx` usam esse stub. Substituir a
  lógica de gating pelo provider/guard client.
- **Não** alterar `metadata.title` ('Keepit Admin') nesta story — fora de
  escopo.

### Decisões / Desvios

- **[AUTO-DECISION] Pub/sub vs. estado no provider (Task 1) → pub/sub (`Set` de listeners) em `adminAuth.ts`** (reason: espelha
  literalmente `onAuthStateChange` do Cliente, deixa `AdminSessionProvider` um consumidor fino do módulo local — mesmo padrão
  arquitetural dos dois lados do app, menor superfície de estado duplicado).
- **`app/page.tsx` (raiz) — Task 4, ponto explicitamente aberto na story: escolhido "redirecionar sempre para `/login`"** em vez de
  tornar a rota raiz `client`. Razão: a rota raiz é um Server Component puro (sem UI própria) e não pode ler `sessionStorage`;
  transformá-la em client só para decidir um redirect adicionaria uma tela de loading desnecessária na raiz. `/login` já resolve o
  bounce para `/aprovacoes` quando há sessão restaurada (AC3), então o usuário autenticado nunca vê o formulário de fato — só um
  redirect extra (raiz → `/login` → `/aprovacoes`), aceitável para uma rota que na prática nunca é o destino de navegação (só é
  acessada digitando a URL base).
- **`proxy.ts` (Next.js 16 "proxy"/ex-middleware) dependia do stub `isAuthenticated()` removido no Task 6.** Não estava listado
  explicitamente nas Tasks, mas ficaria quebrado (import de arquivo deletado) se não fosse tratado. Decisão: simplificar para
  pass-through puro (`NextResponse.next()` sempre), documentando que o gating efetivo agora é 100% client-side
  (`RequireAdminSession`), consistente com a decisão de arquitetura da story ("sem middleware/SSR de auth", Dev Notes). O
  `matcher` foi mantido para não deixar a config órfã e para eventual uso futuro não relacionado a auth.
- Sessão implementada como singleton em módulo (não via `MockDb` do Cliente) — a story já deixa explícito que este mock é local e
  não deve importar `packages/core-data`; um único admin por sessão de navegador não justifica um "banco" mock próprio.
- Status da story foi movido diretamente para **Ready for Review** ao final (conforme instrução explícita do orquestrador que
  spawnou esta execução), pulando o `InReview` intermediário do fluxo padrão `dev-develop-story.md`/`story-lifecycle.md`. Fica
  registrado como desvio de processo, não de escopo — @qa segue como próximo gate obrigatório (CLAUDE.md).

### Riscos avaliados (todos mitigados)

- **SSR / `sessionStorage` no server:** guardado por `typeof window === 'undefined'` em todos os 3 acessos (`loadSession/saveSession/clearSession`). Provider e guard são `'use client'`. Root layout permanece Server Component com apenas o provider como client boundary. OK.
- **Vazamento de sessão entre abas:** `sessionStorage` é isolado por aba — escolha correta; nova aba nasce deslogada. OK.
- **Race no restore:** `ensureRestored()` idempotente (flag `restored`); subscribe dispara callback síncrono, então o primeiro render client já resolve `loading=false` — guard exibe placeholder, nunca pisca `/login` para quem tem sessão. OK.
- **Imports quebrados / `any` perigoso:** nenhum; tipos explícitos (`Admin`, context tipado). OK.

### Observações (LOW — não bloqueiam)

1. **[LOW] Atualização de estado redundante:** `AdminSessionProvider.signIn/signOut` chamam `setAdmin` explicitamente, e o callback do `onAdminAuthStateChange` (disparado por `notify()`) também seta.
