## Story

**As a** novo cliente,
**I want** criar minha conta com nome, e-mail e senha (telefone opcional),
**so that** eu possa começar a comprar.

## Contexto — isto é um DELTA, não UI nova

`apps/cliente/src/screens/auth/CriarConta.tsx` já existe desde o Épico 0 (Story 0.4) e já foi ajustado por uma story anterior a este ponto: título, subtítulo, campos Nome/E-mail/Senha/Telefone, checkbox de termos, botão "Criar conta" e link "Já tem conta? Entrar" já estão implementados, **sem** botões Google/Apple nem separador "ou" (portanto a AC1 do épico, na parte "não renderizar login social", **já está satisfeita hoje** — nada a fazer aí). O trabalho desta story é fechar três divergências pontuais entre o código atual e o épico corrigido (`docs/prd/epics/2-auth-cliente.md`, Story 2.2, seção "Correção de rastreabilidade" de 2026-07-30):

1. **Telefone é obrigatório no código hoje** (`if (!telefone.trim()) nextErrors.telefone = ...`) — o épico (AC2) exige **opcional**. Isso é uma incompatibilidade real com FR1 + decisão 10.4, não uma escolha de UI.
2. **Senha exige mínimo de 6 caracteres no código hoje** (`senha.length < 6`) — o épico (AC2) exige **mínimo de 8**.
3. **Telefone não tem máscara BR** — hoje é um `TextField` de texto livre com `keyboardType="phone-pad"`, sem formatação nem validação de formato quando preenchido (AC4 do épico exige mascarar e validar formato BR **somente se preenchido**).
4. **Bug de navegação pós-submit**: o `handleCriarConta` atual navega para `'ConfirmacaoSMS'` após o mock de `signUp`. A tela `ConfirmacaoSMS` (Story 2.5) e o fluxo de SMS (Story 2.4) foram **removidos do MVP pela decisão 10.4** (2026-07-29) — navegar para lá hoje é um beco sem saída morto no código atual. Esta story corrige o destino para não apontar mais a uma tela fora do fluxo, **sem** implementar a integração real (isso é Story 2.3, que substituirá o `getDataClient().auth.signUp(...)` mock por Supabase Auth e decidirá a navegação de sucesso real, conforme sua própria AC5 — "navega direto para a home"). Ver "Ponto de parada da integração" nas Dev Notes abaixo.

Tudo o mais no arquivo (estrutura visual, copy do título/subtítulo, copy do checkbox, ausência de Google/Apple, campo Nome, validação de e-mail, layout) já está correto e **não deve ser tocado**.
