## Story

**As a** dev solo,
**I want** a fronteira mock/real estabelecida via ports assíncronas + o módulo de placeholders,
**so that** todas as telas consumam dados de forma trocável e nenhum valor de regra fique hard-coded.

## Acceptance Criteria

1. `packages/core-data/src/ports/` define interfaces por domínio (auth, hub, store, product, order, wallet, admin) alinhadas a `docs/architecture/03-data-models.md`.
2. Implementações mock **assíncronas** (Promise + latência configurável) em `packages/core-data/src/mock/`, com fixtures derivadas do protótipo.
3. Factory `createDataClient({ source })` com default `mock`; hooks/providers de consumo (`useOrders()`, `useHubs()`, etc.).
4. Suporte a injeção de estado por chamada: loading / vazio / erro (para as telas exercitarem os três estados).
5. `packages/config` exporta os placeholders financeiros/operacionais (12%, R$ 200, R$ 40, R$ 20, 10 min, 5 tentativas, D+7) num único módulo tipado; mocks e telas leem dele — nunca hard-coded.
6. Testes unitários dos mocks validando o contrato das ports.

### Data Models — mapeamento tabela → domínio (schema real, para as ports não divergirem)

Todas as ports devem espelhar os **nomes de campo em `snake_case`** das tabelas abaixo (não traduzir para camelCase nos tipos que representam o registro — decisão já tomada implicitamente pelo princípio "nomes de campos = colunas reais" do épico; forma de exposição para o app consumidor é decisão do @dev, mas o objeto de domínio deve ser rastreável 1:1 à tabela).

- **auth.port** → tabela `clientes`: `id` (uuid, = `auth.users.id`), `nome`, `telefone`, `telefone_confirmado`, `cpf` (nullable, só após 1º checkout), `bloqueado`, `motivo_bloqueio`, `criado_em`. [Source: docs/architecture/03-data-models.md#1.1 clientes]
  - Confirmação de telefone: tabela `clientes_confirmacao_telefone` (`codigo_hash`, `tentativas`, `expira_em` — 10 min, `consumido_em`). [Source: docs/architecture/03-data-models.md#1.2]
- **hub.port** → tabela `hubs`: `id`, `nome`, `endereco`, `lat`, `lng`, `ponto_referencia`, `foto_url`, `ativo`. Horários: `hubs_horarios` (`dia_semana` 0-6, `aberto`, `hora_abre`, `hora_fecha`). [Source: docs/architecture/03-data-models.md#2]
- **store.port** → tabela `estabelecimentos`: `id`, `nome_fantasia`, `categoria`, `descricao`, `foto_fachada_url`, `endereco`, `lat`, `lng`, `raio_atendimento_km`, `tempo_medio_entrega_min`, `taxa_deslocamento_reais`, `ticket_minimo_reais` (nullable — `COALESCE(loja.ticket_minimo_reais, config.ticketMinimoReais)`), `status` (`em_analise`/`ativo`/`rejeitado`/`suspenso`), `pausado_manualmente`. Horários: `estabelecimentos_horarios` (mesma forma de `hubs_horarios`). [Source: docs/architecture/03-data-models.md#1.4/1.5]
  - "Estado da loja" pedido no AC1 (Aberta/Fechada/Pausada) é **derivado**: `pausado_manualmente = true` → Pausada; fora do horário do dia corrente (`estabelecimentos_horarios`) → Fechada; caso contrário → Aberta. Essa derivação pode viver no mock ou no port como helper — decisão do @dev, documentar.
- **product.port** → tabela `produtos`: `id`, `estabelecimento_id`, `nome`, `descricao`, `preco_reais`, `categoria_produto`, `foto_url`, `ativo`. Nota do schema: **"Não há tabela de estoque"** — decisão de negócio já fechada, não inventar campo de estoque no mock. [Source: docs/architecture/03-data-models.md#3]
- **order.port** → tabela `pedidos`: `id`, `numero`, `cliente_id`, `estabelecimento_id`, `hub_id`, `status` (lista completa de 15 valores no schema — usar exatamente esses literais), `pin_texto` (exibição ao cliente — NUNCA expor `pin_hash`, que é só para persistência real), `tentativas_pin`, `pin_bloqueado_ate`, `tempo_estimado_min`, timestamps de transição (`aceito_em`, `saiu_hub_em`, `cliente_chegou_em`, `lojista_chegou_em`, `entregue_em`, `cancelado_em`), campos financeiros snapshot (`subtotal_produtos_reais`, `taxa_deslocamento_reais`, `taxa_keepit_reais`, `total_pago_reais`), `motivo_recusa`/`motivo_cancelamento`/`motivo_nao_retirado`, `forma_pagamento`. Itens: `pedidos_itens` (`nome_snapshot`, `preco_unitario_reais`, `quantidade`, `subtotal_reais`). [Source: docs/architecture/03-data-models.md#5]
  - Cálculo financeiro do mock (`create`) deve usar `config.taxaKeepitPercent` (12% sobre `subtotal_produtos_reais`, não sobre a taxa de deslocamento) — [Source: docs/PERGUNTAS_REGRAS_NEGOCIO.md — Rodada 6, "Taxa Keepit"].
- **wallet.port** → view `carteira_lojista`: `saldo_disponivel_reais`, `saldo_bloqueado_reais`, `total_sacado_reais`, `total_debitado_reais`. Saques: tabela `saques` (`valor_reais` >= `config.saqueMinimoReais`, `status`). [Source: docs/architecture/03-data-models.md#6.2/6.5]
- **admin.port** → `estabelecimentos.status` para aprovação/rejeição (`em_analise` → `ativo`/`rejeitado`, com `motivo_rejeicao`); `reembolsos_pendentes` (`motivo` — lista de 9 valores no schema, `status` `pendente_admin`/`em_processamento`/`estornado`/`erro`, `valor_a_estornar_reais`, `valor_ao_lojista_reais`). [Source: docs/architecture/03-data-models.md#1.4/#6.1]
