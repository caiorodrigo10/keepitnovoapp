## Story

**As a** dev solo,
**I want** os 3 apps (`apps/cliente`, `apps/lojista`, `apps/admin`) bootados de verdade renderizando uma Home mínima com tokens e fontes oficiais,
**so that** eu prove que a stack de renderização está viva — sem nenhum backend — antes de construir todas as telas do Épico 0.

## Acceptance Criteria

1. Fontes Hanken Grotesk disponíveis em `.woff2` **e `.ttf`** (iOS) para os pesos Regular, Medium, SemiBold, Bold, ExtraBold em `packages/ui-tokens/fonts/`.
2. `apps/cliente` e `apps/lojista` bootados com Expo (SDK estável mais recente), fontes carregadas via `useFonts`, abrindo no simulador iOS e no emulador Android.
3. `apps/admin` bootado com Next.js (App Router), Tailwind consumindo `packages/ui-tokens/src/tailwind.js`, `@font-face` das fontes locais (via `next/font/local`).
4. Cada app exibe uma Home mínima com a paleta correta — Cliente claro `#F6F7F3`, Lojista dark `#1B1E1C`, Admin dark — como prova de vida = render fiel, **sem** leitura a backend.
5. `pnpm turbo run dev` levanta os três apps (Expo Cliente, Expo Lojista, Next.js Admin) simultaneamente.

### Completion Notes List — Fix Iteration (QA Loop, pós-FAIL)

**REQ-001 (high, bloqueante) — RESOLVIDO.**
Causa raiz confirmada: `next/font/local` (em `apps/admin/app/layout.tsx`) gera `@font-face { font-family: hanken }` e expõe a CSS var `--font-hanken` via `hanken.variable` no `<html>`, mas `fontFamily.sans` no preset compartilhado (`packages/ui-tokens/src/tailwind.js`) usava o nome literal `"Hanken Grotesk"`, que não casava com nenhum `@font-face` — o `<body>` (`font-sans`) caía para `system-ui`.
