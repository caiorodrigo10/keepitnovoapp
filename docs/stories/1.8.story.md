# Story 1.8: Deploy automático do Admin na Vercel

## Status

Draft

## Escopo desta story

- **Somente o deploy.** O boot do `apps/admin` (Next.js App Router + Tailwind com
  tokens do `ui-tokens` + tela de login placeholder) foi **migrado para o Épico 0
  (Story 0.1)** e já está `Done`. Esta story cobre **exclusivamente** as AC 4 e 5 da
  Story 1.8 original do Épico 1: conectar o repositório à Vercel e ter uma URL pública
  disparando deploy automático a cada commit em `main`.
  [Fonte: `docs/prd/epics/1-setup-fundacao.md`, Story 1.8 — nota de reorganização
  2026-07-27 e AC 4/5]

## Dependencies

- **Épico 0, Story 0.1 (boot do admin)** — `Done`. `apps/admin` já builda como app
  Next.js.
- **Variável externa — conta Vercel.** Requer uma conta Vercel com acesso ao
  repositório GitHub do monorepo. Sem essa conta/credencial, a story **não pode ser
  concluída** (bloqueio externo, análogo ao CI da Story 1.5).

## Complexidade

**Baixa — configuração de infra, não desenvolvimento.** O trabalho é conectar o repo,
configurar root directory + build command do workspace, e validar a URL. Nenhuma linha
de código de aplicação.

## Story

**As a** dev solo,
**I want** o `apps/admin` conectado à Vercel com deploy automático a cada commit em `main`,
**so that** eu tenha desde já uma URL de admin pública e sempre atualizada, sem deploy manual.

## Acceptance Criteria

1. Projeto Vercel criado e **conectado ao repositório** do monorepo, com o **root
   directory** apontando para `apps/admin` e o build resolvendo o workspace pnpm
   (Turborepo/pnpm workspaces) sem erro de dependência `workspace:*`.
   [Fonte: `docs/prd/epics/1-setup-fundacao.md`, Story 1.8 AC4]
2. **Commit em `main` dispara deploy automático** (Production). Um commit de teste
   resulta em novo deploy visível no painel da Vercel.
   [Fonte: idem, AC4]
3. **URL pública funciona** e renderiza a tela de login placeholder do admin (a mesma
   entregue na Story 0.1), na paleta dark do lojista/admin.
   [Fonte: idem, AC5]
4. Variáveis de ambiente necessárias ao build (ex.: `DATA_SOURCE`) configuradas no
   projeto Vercel, mantendo o admin em mock enquanto o backend real não é ligado —
   nenhum segredo de produção commitado no repo.
5. O DoD do Épico 1 é atualizado: item **"Deploy admin na Vercel funcionando"** marcado,
   e a linha "1.8-deploy (Vercel) ⬜" vira ✅.
   [Fonte: `docs/prd/epics/1-setup-fundacao.md`, Definition of Done]

## Out of Scope

- Boot/renderização do admin (feito no Épico 0).
- Autenticação real do admin (Épico 3/8).
- Domínio customizado — a URL `*.vercel.app` basta para o MVP.

## Riscos

- **Bloqueio externo:** depende de conta Vercel provisionada. Enquanto não houver, a
  story fica `Draft`/`Blocked`, análogo ao CI (Story 1.5, AC3 waived).
- **Resolução de workspace na Vercel:** monorepos pnpm exigem root directory + install
  command corretos; um deploy que ignore o workspace quebra em `workspace:*`. Validar no
  primeiro deploy.

## Definition of Done

- [ ] AC 1–5 atendidas.
- [ ] Deploy de produção verde na Vercel a partir de `main`.
- [ ] URL pública validada renderizando a tela de login placeholder.
- [ ] DoD do Épico 1 atualizado.
