## Story

**As a** dev solo,
**I want** as telas de entrada do lojista (onboarding, cadastro em 3 passos, "em análise", login, perfil público e configurações) navegáveis e fiéis ao protótipo dark do App Lojista,
**so that** eu tenha o fluxo completo de captação de lojista pronto para revisão de UX/fidelidade, sem nenhuma persistência, autenticação ou validação real de CNPJ.

## Acceptance Criteria

1. Telas: Onboarding lojista, Cadastro passo 1 (dados básicos), passo 2 (operacionais: raio de atendimento, tempo médio), passo 3 (recebimento + fachada + horários), "Em análise", Login, Perfil público (editar), Configurações + Excluir conta.
2. Tema dark fiel ao protótipo (`#1B1E1C` e paleta `colors.dark` de `packages/ui-tokens`).
3. Sem validação de CNPJ real; campos renderizados, submit apenas navega.
4. Fidelidade visual verificada contra o protótipo.

```
nome_fantasia text NOT NULL
cnpj text NOT NULL UNIQUE
responsavel_nome text NOT NULL
telefone text NOT NULL
categoria text NOT NULL          -- valores de exemplo vistos no protótipo: 'Farmácia'; CHECK completo não documentado — não inventar a lista completa, confirmar com @po/stakeholder antes do Épico 1
```

### Conflito schema vs. protótipo — campo "Hub de operação"

O protótipo (painel P6, Cadastro passo 1) exibe um campo dropdown **"Hub de operação"** com um único hub selecionado (ex.: "Hub Centro"). Porém a tabela `estabelecimentos` (schema real, `docs/architecture/03-data-models.md#1.4`) **não tem coluna `hub_id`** — a única referência a hub no schema fica em `pedidos.hub_id` (por pedido, não por loja), e a cobertura geográfica da loja é resolvida por `lat`/`lng` + `raio_atendimento_km`. [Source: docs/architecture/03-data-models.md#5.1 `pedidos`, #1.4 `estabelecimentos`]

**Decisão para esta story:** manter o campo "Hub de operação" na Task 4 por fidelidade visual ao protótipo (AC4 exige isso), mas tratá-lo como um campo **exclusivo do mock/UI desta story** — não nomear como se fosse uma coluna confirmada do schema real (ex.: usar algo como `hubPreferencialId` no shape do formulário local, claramente comentado como "não corresponde a coluna confirmada em `estabelecimentos`; aguardando decisão de arquitetura/stakeholder"). Não modelar isso como parte de uma port real de `packages/core-data` nesta story (a Story 0.2 ainda não existe) — é só estado de formulário local.
