## Status

## MVP Pilot Classification

- Classificação: UI_ONLY (infra de build; sem regra de negócio)
- Fonte: `docs/prd/epics/9-publicacao-compliance.md` (Fase 0-Android — Piloto Google Play Internal Testing)
- Backend esperado: nenhum. O bloco `android` do profile `pilot` deve gerar
  um AAB fixado em `DATA_SOURCE=mock` (o mesmo `env` já compartilhado com
  iOS) e impedir qualquer build do piloto Android de apontar para

  equivalente para Android, com `DATA_SOURCE=supabase` e segredos reais — não

  dados mock à produção ou vice-versa).

## Data Mode

- Entidades: nenhuma diretamente — esta story só edita `eas.json` (config de
  build), sem tocar `packages/core-data` nem qualquer tela.
- Modo padrão: mock. Esta story **reforça mecanicamente** o modo de dados do
  build Android do piloto, usando o **mesmo** bloco `env.DATA_SOURCE=mock` já
  presente no profile `pilot` (nível do profile, válido para as duas
  plataformas) — não cria um `env` novo nem duplicado para Android.
- Modo real: `DATA_SOURCE=supabase` — não usado nesta fase; fora do escopo
  desta story.
- Compatibilidade mock: nenhuma fixture tocada; a garantia real de mock
  continua sendo code-level (`resolveDataSource()` default `'mock'`,
  confirmado na Story 9.0.2), o `env` do `eas.json` é documental/defensivo —
  mesma ressalva técnica já registrada na 9.0.2, válida também para Android.

## Dependencies

## Story

**As a** dev,
**I want** o profile `pilot` do EAS com um bloco `android` que gere AAB e um
bloco de `submit` apontando para a faixa Internal Testing,
**so that** o build Android do piloto seja gerado no formato certo e enviado
ao destino certo, sem duplicar a trava de `DATA_SOURCE=mock` já existente.

## Acceptance Criteria

1. O profile `pilot` dos dois `eas.json` (`apps/cliente/eas.json`,
   `apps/lojista/eas.json`) recebe `"android": { "buildType": "app-bundle" }`
   — gera AAB, formato exigido pelo Google Play (o mesmo profile que já gera
   IPA para iOS passa a gerar AAB para Android, sem mudar `distribution`,
   que já é `"store"` — correto e favorável ao alvo Android). [Fonte:
   `docs/architecture/08-mvp-pilot-android.md` §3.2 item 1]
2. `env.DATA_SOURCE=mock` **não é duplicado nem divergido** para Android — o
   `env` já existe no nível do profile `pilot` (Story 9.0.2) e vale para
   ambas as plataformas automaticamente. Esta story confirma essa herança por
   leitura, sem criar um bloco `env` novo dentro de `android`. [Fonte:
   `docs/architecture/08-mvp-pilot-android.md` §3.2 item 1, §9]
3. `submit.pilot.android` adicionado nos dois `eas.json`, com
   `serviceAccountKeyPath` apontando para um caminho de arquivo fora do
   repositório (segredo — gerado por @devops na Story 9.0.11, não committado
   nesta story nem em nenhuma) e `track: "internal"` (faixa Internal
   Testing). [Fonte: `docs/architecture/08-mvp-pilot-android.md` §3.2 item 2]
4. O arquivo (ou Dev Notes deste story file) documenta que o profile `pilot`
   Android é exclusivo do piloto interno e não serve para produção — mesma
   disciplina já aplicada ao bloco iOS na Story 9.0.2 (o `eas.json` é JSON
   estrito, sem comentários; a documentação vive no story file e no épico).
   [Fonte: `docs/architecture/08-mvp-pilot-android.md` §3.2 item 2]
5. `credentialsSource` permanece coerente com a decisão de keystore (Opção A
   — EAS-managed, recomendação do arquiteto): **não** adicionar
   `credentialsSource: "local"` para Android (diferente do iOS, que já usa
   `local` para suas próprias credenciais Apple) — deixar o EAS gerenciar a
   keystore Android remotamente. [Fonte: `docs/architecture/08-mvp-pilot-android.md` §3.2 item 3, §5]
6. `.gitignore` cobre os padrões de segredo Android do piloto: arquivo de
   service account (`*serviceAccount*.json` ou equivalente) e, se algum dia a
   Opção B (keystore local) for adotada, `*.jks` — hoje o `.gitignore` só
   cobre `apps/*/credentials.json`/`apps/*/credentials/` (Apple); esta story
   adiciona os padrões Android correspondentes, mesmo sem gerar nenhum
   arquivo de segredo real (isso é @devops, Story 9.0.11). [Fonte:
   `docs/architecture/08-mvp-pilot-android.md` §5, "Red flag de gitignore"]

## Dev Notes

### Herança do `env.DATA_SOURCE=mock` — não duplicar

A Story 9.0.2 já fixou `env.DATA_SOURCE=mock` no **nível do profile**
`pilot` (não dentro de `ios`), exatamente para que a mesma trava valesse
para qualquer plataforma adicionada depois. Esta story **não** deve
adicionar um `env` dentro do novo bloco `android` — isso criaria risco de
divergência (ex.: alguém editar só o bloco Android e esquecer o iOS, ou
vice-versa). A trava documental permanece única e compartilhada.

### `distribution: "store"` já é o valor correto para Android (nota de reconciliação com a AC2 original do épico)

O `eas.json` atual usa `"distribution": "store"` (não `"internal"`, como a
AC2 original da Story 9.0.2 no épico dizia — o arquivo real ficou `"store"`,
que é o que serve para submeter à loja). Isso é **favorável** ao Android:
`store` produz um binário assinável para o Play Console (AAB via
`buildType: "app-bundle"`); `internal` produziria um APK para sideload. O
mesmo profile que gera IPA para iOS passa a gerar AAB para Android sem
qualquer mudança em `distribution`. [Fonte: `docs/architecture/08-mvp-pilot-android.md` §2, nota]

### Keystore — Opção A (EAS-managed), recomendação do arquiteto

Diferente do iOS (`credentialsSource: "local"`, com `dist.p12` e
`.mobileprovision` no repo, ignorados no git), a recomendação para Android é
deixar o **EAS gerenciar a keystore (upload key)** no servidor, sem nenhum
arquivo de credencial Android no repositório. O Google Play App Signing
assume a chave de assinatura final. Esta é uma decisão orquestrada por
plataforma — o iOS seguir `local` não obriga o Android a seguir o mesmo
caminho. A execução/gestão real da keystore é exclusiva de @devops (Story
9.0.12), não desta story. [Fonte: `docs/architecture/08-mvp-pilot-android.md` §5]

### `serviceAccountKeyPath` — segredo, nunca committado

O JSON do service account do Google Cloud/Play (equivalente à ASC API key do
iOS) só é **gerado** na Story 9.0.11 (@devops). Esta story apenas declara o
caminho esperado no `eas.json` e garante que o `.gitignore` cobre esse
padrão — não cria nem referencia um arquivo real.

### Arquivos exatos

**Modifica:**
- `apps/cliente/eas.json`
